## 第 3 题

Q: RAG 相比纯大模型回答有哪四个核心优势？

A: RAG 相比纯大模型回答有四个核心优势：

1. 降低幻觉：答案基于事实依据，而非模型的“记忆”。
2. 数据私有化：无需微调模型，即可利用企业私有数据。
3. 可解释性：可以提供引用来源，用户可以验证答案的真伪。
4. 成本效益：避免了高昂的全量微调成本。

Q: 为什么 RAG 要把文档切分成小块（chunk）？两种切分策略各有什么特点？

## 第 6 题

Q: ReAct 的全称是什么？它的核心目标是什么？

A: ReAct 的全称是 Reasoning + Acting（推理 + 行动）。其核心目标是打破传统语言模型“输入-输出”的单向链路，构建“感知-决策-执行-反馈”的智能闭环，使模型从“被动应答者”升级为“主动问题解决者”。

## 第 7 题

Q: ReAct 的 TAO 循环由哪三部分组成？各自的作用是什么？

A: ReAct 的 TAO 循环由三部分组成：

1. **Thought（推理）**：模型的“内心独白”，用于分析任务目标、历史反馈和当前状态，明确下一步行动的逻辑依据。
2. **Act（行动）**：模型与外部交互的“执行动作”，如调用搜索引擎、计算工具或控制设备。
3. **Observe（观察）**：外部环境对行动的“客观反馈”，如搜索结果、计算答案，为下一轮推理提供真实数据支撑。

## 第 8 题

Q: RAG 系统自动化评估中常用的三个指标是什么？

A: 根据参考资料，RAG 系统自动化评估中常用的三个指标是：上下文召回率（Context Recall）、上下文精确率（Context Precision）和答案相关性（Answer Relevance）。

## 第 12 题

Q: RAG 技术经历了哪些范式演进？各范式的主要特点是什么？

A: 根据参考资料，RAG 技术的范式演进如下：

1. **Naive RAG**：早期的基础范式，传统流程包括索引、检索、生成三个步骤，但存在一定局限性。
2. **Advanced RAG**：针对 Naive RAG 的局限引入改进，包括检索前/检索后策略、改进索引技术（如滑动窗口、细粒度分割、元数据整合）以及多种检索优化方法。
3. **Modular RAG**：作为第三种范式出现，资料中未详细展开其具体特点。
4. **GraphRAG**：2024 年微软开源，是第四种范式，融合了知识图谱。
5. **Agentic RAG**：2024 年下半年出现，是前四种范式的集大成者，具有自适应性。

## 第 13 题

Q: 为什么说「检索质量决定 RAG 回答的上限」？有哪些手段改进检索？

A: 根据参考资料，检索质量之所以决定 RAG 回答的上限，是因为检索结果直接决定了后续生成所依据的上下文质量。资料中提到，初步检索可能会引入噪声，而不够精确的检索结果会限制最终答案的准确性。

改进检索的手段包括：
- 使用更高质量的嵌入模型（如 all-mpnet-base-v2）
- 调整块大小和重叠参数
- 增加检索文档数量
- 实现重排序（如引入重排序模型对初步检索结果进行精排，剔除不相关内容）
- 采用检索前和检索后策略
- 改进索引技术，如使用滑动窗口方法、细粒度分割和元数据的整合

资料中相关内容为：“检索质量差：使用更高质量的嵌入模型（如 all-mpnet-base-v2）、调整块大小和重叠参数、增加检索文档数量、实现重排序”，以及“为了提高检索质量，采用检索前和检索后策略；为了解决索引问题，通过使用滑动窗口方法、细粒度分割和元数据的整合，改进了索引技术”。

## 第 19 题

Q: ReAct 中 Thought、Act、Observe 为什么要按顺序循环？少了 Observe 会怎样？

A: 根据资料，ReAct 的循环按“Thought→Act→Observe”顺序进行，其中 Observe 是外部环境对行动的“客观反馈”，为下一轮推理提供真实数据支撑。因此，缺少 Observe 会导致模型无法获取外部反馈，后续推理失去真实数据依据，难以继续正确决策。

## 第 20 题

Q: 「回答正确」和「回答有依据」是一回事吗？RAG 评估里怎么区分它们？

A: 资料中，“回答正确”和“回答有依据”不是一回事。在 RAG 评估中，“回答有依据”对应上下文召回率和上下文精确率，分别衡量检索内容是否覆盖了答案所需的事实、检索内容是否真正有助于回答；而“回答正确”对应答案相关性，衡量生成的答案是否与问题相关且准确。
