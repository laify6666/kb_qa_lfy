## 第 1 题

Q: RAG 的全称和核心思想是什么？

A: RAG 的核心思想在资料中有明确说明：**让大模型“先查资料，再回答”**。具体流程包括三个主要步骤：

- **检索（Retrieval）**：从外部知识库中检索与问题最相关的片段。
- **增强（Augmentation）**：将检索到的片段与用户问题拼接，形成包含上下文提示的 Prompt。
- **生成（Generation）**：将增强后的 Prompt 发送给大模型，基于参考资料生成最终答案。

关于 **RAG 的全称**，参考资料中未明确写出完整英文全称；但根据资料中给出的三个步骤英文（Retrieval、Augmentation、Generation）可对应为 Retrieval-Augmented Generation。

## 第 2 题

Q: 传统 RAG 流程的三个主要步骤是什么？

A: 根据参考资料，传统 RAG 流程的三个主要步骤是：

1. 检索（Retrieval）：当用户提出问题时，系统先从外部知识库（如向量数据库、文档）中检索出与问题最相关的片段。
2. 增强（Augmentation）：将检索到的相关片段与用户的问题拼接，形成一个新的、包含上下文提示的 Prompt。
3. 生成（Generation）：将增强后的 Prompt 发送给 LLM，LLM 基于提供的参考资料生成最终答案。

## 第 3 题

Q: RAG 相比纯大模型回答有哪四个核心优势？

A: RAG 相比纯大模型回答的四个核心优势是：

1. 降低幻觉：答案基于事实依据，而非模型的“记忆”。
2. 数据私有化：无需微调模型，即可利用企业私有数据。
3. 可解释性：可以提供引用来源，用户可以验证答案的真伪。
4. 成本效益：避免了高昂的全量微调成本。

## 第 4 题

Q: 为什么 RAG 要把文档切分成小块（chunk）？两种切分策略各有什么特点？

A: 根据参考资料，RAG 需要将文档切分成小块，是因为原始数据（如 PDF、Word、网页等）通常是非结构化的，需要将其加载为文本，并切分成较小的块（Chunks），以便后续为每个文本块生成向量表示并进行检索。切分策略会直接影响检索质量。

两种切分策略的特点如下：

- **固定大小切分**：简单，但可能切断语义完整性。
- **递归字符切分**：按段落、句子递归切分，能保留更多语义结构。

## 第 5 题

Q: 什么是文本嵌入（Embedding）？语义相似的文本在向量空间中有什么关系？

A: 根据参考资料，文本嵌入（Embedding）是将文本转换为数值向量的过程：计算机无法直接理解语义，需要通过嵌入模型将文本映射到多维向量空间中。语义相似的文本，其向量距离在空间中也会相近。

## 第 6 题

Q: ReAct 的全称是什么？它的核心目标是什么？

A: ReAct 的全称是 **Reasoning（推理）+ Acting（行动）**。

其核心目标是：**打破传统语言模型“输入-输出”的单向链路，构建“感知-决策-执行-反馈”的智能闭环，使模型从“被动应答者”升级为“主动问题解决者”**。

## 第 7 题

Q: ReAct 的 TAO 循环由哪三部分组成？各自的作用是什么？

A: ReAct 的 TAO 循环由以下三部分组成：

1. **Thought（推理）**：模型的“内心独白”，用于分析任务目标、历史反馈和当前状态，明确下一步行动的逻辑依据。
2. **Act（行动）**：模型与外部交互的“执行动作”，如调用搜索引擎、计算工具或控制设备。
3. **Observe（观察）**：外部环境对行动的“客观反馈”，如搜索结果、计算答案，为下一轮推理提供真实数据支撑。

## 第 8 题

Q: RAG 系统自动化评估中常用的三个指标是什么？

A: RAG 系统自动化评估中常用的三个指标是：

1. 上下文召回率（Context Recall）：检索到的内容是否覆盖了答案所需的所有事实。
2. 上下文精确率（Context Precision）：检索到的内容是否真的有助于回答。
3. 答案相关性（Answer Relevance）：生成的答案是否与问题相关且准确。

## 第 9 题

Q: 什么是 GraphRAG？它主要擅长解决哪类问题？

A: 根据参考资料，GraphRAG 利用实体间的结构信息，实现更精确、更全面的检索，捕捉关系知识。工作流程包括：

- **基于图形的索引（G-Indexing）**
- **图形引导的检索（G-Retrieval）**

GraphRAG 通过 LLM 构建图索引：先从文档中提取实体图，再预生成相关实体的摘要；回答问题时，每个摘要生成部分答案，最终汇总为完整回答。

它主要擅长解决**全局性问题**，例如“数据集的主要主题是什么？”这类问题，能显著提升答案的全面性和多样性。

## 第 12 题

Q: RAG 技术经历了哪些范式演进？各范式的主要特点是什么？

A: 根据参考资料，RAG 技术的范式演进及特点如下：

### 一、范式演进历程
- 自 2021 年 RAG 技术出现后，首先被用于 LLMs 的预训练阶段，随后用于微调与推理任务。
- 自 ChatGPT 发布以来，用于推理阶段的 RAG 方法迅速演化出**三种范式**：**NaiveRAG、AdvancedRAG 与 ModularRAG**。
- 2024 年，微软开源的 **GraphRAG** 开启了第四种范式，融合了知识图谱。
- 2024 年下半年，**AgenticRAG** 出现，是前四种范式的集大成者，且具有自适应性。

### 二、各范式的主要特点
- **NaiveRAG、AdvancedRAG、ModularRAG**：参考资料仅提及它们是推理阶段演化出的三种范式，未详细说明各自的具体特点。
- **GraphRAG**：
  - 融合知识图谱，利用实体间的结构信息，实现更精确、更全面的检索，捕捉关系知识。
  - 工作流程包括基于图形的索引（G-Indexing）、图形引导的检索（G-Retrieval）和图形增强的生成（G-Generation）。
  - 通过 LLM 构建图索引：先从文档中提取实体图，再预生成相关实体的摘要；回答问题时，每个摘要生成部分答案，最终汇总为完整回答。
  - 在处理全局性问题（如“数据集的主要主题是什么？”）时，能显著提升答案的全面性和多样性。
  - 相关系统还有 LightRAG，将图结构纳入文本索引和检索过程，采用双层检索系统，支持增量更新。
- **AgenticRAG**：
  - 将 ReAct 的推理能力与 Agent 的任务执行能力相结合，创建一个动态和自适应的系统。
  - 与遵循固定管道的传统 RAG 不同，它通过使用 ReAct 根据用户查询的上下文动态协调 Agent，引入了灵活性。
  - 模型不再仅限于被动响应用户查询；相反，它可以主动规划、执行并调整其方法以独立解决问题。
  - 能够处理更复杂的任务，动态适应新挑战。

## 第 13 题

Q: 为什么说「检索质量决定 RAG 回答的上限」？有哪些手段改进检索？

A: 根据参考资料，可以这样理解“检索质量决定 RAG 回答的上限”：RAG 的流程是先检索、再生成，生成阶段只能基于检索到的内容作答。如果检索到的内容不相关、不完整或有噪声，LLM 即使能力再强，也无法生成准确的答案。资料中也提到“初步检索可能会引入噪声”，因此检索质量直接限制了最终回答的准确性。

资料中提到的改进检索质量的手段主要有以下几类：

1. **检索前和检索后策略**：高级 RAG 为提高检索质量，会采用检索前和检索后的优化策略。
2. **改进索引技术**：
   - 使用滑动窗口方法；
   - 细粒度分割；
   - 整合元数据。
3. **调整检索参数与模型**：
   - 使用更高质量的嵌入模型（如 all-mpnet-base-v2）；
   - 调整块大小和重叠参数；
   - 增加检索文档数量；
   - 实现重排序（Reranking）。
4. **重排序（Reranking）**：
   - 使用 Cross-Encoder 模型（如 BGE-Reranker）对向量检索出的 Top-K 结果进行精排，剔除不相关内容，保留最精准的片段。虽然增加计算延迟，但能显著提升最终答案的准确性。
5. **评估与优化循环**：
   - 使用 RAGAS 或 DeepEval 等框架自动化评估，关注上下文召回率（检索到的内容是否覆盖答案所需事实）和上下文精确率（检索到的内容是否真正有助于回答），从而持续改进检索质量。

总之，检索阶段决定了送入生成模型的上下文质量，因此是 RAG 回答效果的关键瓶颈；通过上述多种手段，可以从索引、检索、重排序和评估等方面全方位提升检索质量。

## 第 19 题

Q: ReAct 中 Thought、Act、Observe 为什么要按顺序循环？少了 Observe 会怎样？

A: 根据参考资料，ReAct 将 **Thought → Act → Observe** 抽象为 **TAO 闭环**，三者必须按顺序循环，原因如下：

1. **Thought（推理）** 是模型的“内心独白”，用于分析任务目标、历史反馈和当前状态，明确下一步行动的逻辑依据。
2. **Act（行动）** 是模型与外部交互的“执行动作”，将推理结果转化为标准化指令，调用工具或完成任务。
3. **Observe（观察）** 是外部环境对行动的“客观反馈”，为下一轮推理提供真实数据支撑。

只有按“推理 → 行动 → 观察 → 推理 → …”的顺序循环，才能形成“感知-决策-执行-反馈”的智能闭环，让模型基于真实反馈不断调整行动，而非单向输出。

**如果少了 Observe，会怎样？**

- 模型无法获得外部环境对行动的客观反馈，后续的 Thought 就缺少真实数据作为依据；
- 推理轨迹无法根据行动结果更新，模型难以判断当前任务进展是否正确；
- 模型只能依赖内部知识生成结论，违背了“外部环境锚定原则”，容易产生事实幻觉；
- TAO 闭环被破坏，任务无法在真实反馈驱动下持续推进，很可能导致任务失败或输出不可靠结果。

## 第 20 题

Q: 「回答正确」和「回答有依据」是一回事吗？RAG 评估里怎么区分它们？

A: 根据参考资料，RAG 评估体系通过不同指标来区分“回答正确”和“回答有依据”，二者不是一回事：

- **“回答有依据”** 对应检索环节的评估指标：
  - **上下文召回率（Context Recall）**：衡量检索到的内容是否覆盖了答案所需的所有事实。
  - **上下文精确率（Context Precision）**：衡量检索到的内容是否真的有助于回答。

- **“回答正确”** 对应生成环节的评估指标：
  - **答案相关性（Answer Relevance）**：衡量生成的答案是否与问题相关且准确。

也就是说，“有依据”侧重评估检索回来的资料是否充分、有用；而“回答正确”侧重评估最终生成的答案本身是否准确、相关。参考资料中明确列出了这些评估指标，并说明使用 RAGAS 或 DeepEval 等框架进行自动化评估。

## 第 35 题

Q: normalize 函数的作用是什么？

A: 根据参考资料，`normalize` 函数的作用是**对输入的嵌入向量进行 L2 范数归一化处理**，具体包括：

- 计算每个嵌入向量的 L2 范数。
- 将每个向量的元素分别除以其 L2 范数。
- 使得所有嵌入向量都被规范化到单位球上。

这样做的目的是**优化向量的表示和后续使用**，有助于提高向量空间模型中后续处理的效果和稳定性。在项目中，该函数被 `embed_documents`、`embed_query`、`aembed_documents`、`aembed_query` 等方法调用，用于对文档和查询的嵌入结果进行归一化，以确保嵌入向量的质量。
