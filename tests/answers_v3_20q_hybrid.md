## 第 1 题

Q: RAG 的全称和核心思想是什么？

A: 根据参考资料，RAG 的全称在资料中未明确写出；但其核心思想在资料中有明确说明：**“让大模型‘先查资料，再回答’”**。具体来说，RAG 通过检索、增强、生成三个步骤，从外部知识库中检索相关片段，与用户问题拼接成增强后的 Prompt，再交由大模型生成基于参考资料的回答。

## 第 2 题

Q: 传统 RAG 流程的三个主要步骤是什么？

A: 根据参考资料，传统 RAG 流程的三个主要步骤是：

1. **检索（Retrieval）**：当用户提出问题时，系统先从外部知识库（如向量数据库、文档）中检索出与问题最相关的片段。
2. **增强（Augmentation）**：将检索到的相关片段与用户的问题拼接，形成一个新的、包含上下文提示的 Prompt。
3. **生成（Generation）**：将增强后的 Prompt 发送给 LLM，LLM 基于提供的参考资料生成最终答案。

## 第 3 题

Q: RAG 相比纯大模型回答有哪四个核心优势？

A: 根据参考资料，RAG 相比纯大模型回答的四个核心优势是：

1. **降低幻觉**：答案基于事实依据，而非模型的"记忆"。
2. **数据私有化**：无需微调模型，即可利用企业私有数据。
3. **可解释性**：可以提供引用来源，用户可以验证答案的真伪。
4. **成本效益**：避免了高昂的全量微调成本。

## 第 4 题

Q: 为什么 RAG 要把文档切分成小块（chunk）？两种切分策略各有什么特点？

A: 根据参考资料，将文档切分成小块（Chunks）的原因在于：原始数据（如 PDF、Word、网页等）通常是非结构化的，需要加载为文本并切分成较小的块，切分策略直接影响检索质量。

两种切分策略的特点：

- **固定大小切分**：简单，但可能切断语义完整性。
- **递归字符切分**：按段落、句子递归切分，保留更多语义结构。

## 第 6 题

Q: ReAct 的全称是什么？它的核心目标是什么？

A: ReAct 的全称是 Reasoning + Acting（推理 + 行动）。它的核心目标是打破传统语言模型“输入-输出”的单向链路，构建“感知-决策-执行-反馈”的智能闭环，使模型从“被动应答者”升级为“主动问题解决者”。

## 第 7 题

Q: ReAct 的 TAO 循环由哪三部分组成？各自的作用是什么？

A: 根据参考资料，ReAct 的 TAO 循环由以下三部分组成：

- **Thought（推理）**：模型的“内心独白”，用于分析任务目标、历史反馈和当前状态，明确下一步行动的逻辑依据。
- **Act（行动）**：模型与外部交互的“执行动作”，如调用搜索引擎、计算工具或控制设备。
- **Observe（观察）**：外部环境对行动的“客观反馈”，如搜索结果、计算答案，为下一轮推理提供真实数据支撑。

## 第 8 题

Q: RAG 系统自动化评估中常用的三个指标是什么？

A: RAG 系统自动化评估中常用的三个指标是：

1. **上下文召回率（Context Recall）**：检索到的内容是否覆盖了答案所需的所有事实。
2. **上下文精确率（Context Precision）**：检索到的内容是否真的有助于回答。
3. **答案相关性（Answer Relevance）**：生成的答案是否与问题相关且准确。

## 第 9 题

Q: 什么是 GraphRAG？它主要擅长解决哪类问题？

A: 根据参考资料，GraphRAG 是 RAG 的第四种范式，融合了知识图谱，利用实体间的结构信息实现更精确、更全面的检索，捕捉关系知识。其工作流程包括基于图形的索引（G-Indexing）、图形引导的检索（G-Retrieval）和图形增强的生成（G-Generation）。GraphRAG 通过 LLM 构建图索引：先从文档中提取实体图，再预生成相关实体的摘要；回答问题时，每个摘要生成部分答案，最终汇总为完整回答。

它主要擅长解决**全局性问题**（如“数据集的主要主题是什么？”），能够显著提升答案的全面性和多样性。

## 第 13 题

Q: 为什么说「检索质量决定 RAG 回答的上限」？有哪些手段改进检索？

A: 「检索质量决定 RAG 回答的上限」是因为 RAG 的生成阶段完全依赖于检索到的内容：系统先检索出与问题最相关的文档片段，再将片段与问题一起输入 LLM 生成答案。如果检索到的片段不相关、不完整或包含噪声，LLM 即使能力再强，也无法基于错误的上下文给出准确答案——生成质量被检索结果所限制。因此，检索环节是 RAG 系统的关键瓶颈。

改进检索质量的手段包括：

- 使用更高质量的嵌入模型（如 all-mpnet-base-v2）。
- 调整块大小和重叠参数，使分块更合理。
- 增加检索文档数量（Top K）。
- 实现重排序（Reranking）：使用 Cross-Encoder 模型（如 BGE-Reranker）对向量检索出的 Top-K 结果进行精排，剔除不相关内容，保留最精准的片段。
- 采用检索前和检索后策略（高级 RAG 的改进措施）。
- 改进索引技术，如使用滑动窗口方法、细粒度分割和元数据的整合。

## 第 19 题

Q: ReAct 中 Thought、Act、Observe 为什么要按顺序循环？少了 Observe 会怎样？

A: 根据参考资料，ReAct 中 Thought、Act、Observe 按顺序循环的原因及缺少 Observe 的后果如下：

1. **形成闭环，驱动迭代**：ReAct 将“推理→行动→观察”抽象为 TAO 闭环，每轮迭代严格遵循“推理-行动-观察”的顺序，上下文管理器将本轮三元组追加到历史轨迹，进入下一轮迭代。Observe 是闭环中承上启下的关键环节。

2. **Observe 提供真实数据支撑**：Observe 是外部环境对行动的“客观反馈”（如搜索结果、计算答案），能为下一轮推理提供真实数据支撑。缺少 Observe，模型就无法获得外部工具执行后的反馈，推理将失去客观依据。

3. **抑制事实幻觉**：ReAct 强调“外部环境锚定”，通过调用外部工具获取客观反馈，将推理过程锚定到真实数据，从根源上抑制“事实幻觉”。缺少 Observe，模型只能依赖内部知识，容易生成脱离事实的结论。

4. **影响决策逻辑与可解释性**：Thought 需要基于“任务目标 + 历史 TAO 轨迹”生成推理，其中历史轨迹包含 Observe 的结果。缺少 Observe，模型无法准确判断“当前任务进展”和“下一步行动方案”，导致决策逻辑断裂，也不符合“可解释性优先原则”。

5. **导致任务无法正常推进**：如果没有 Observe，上下文管理器中缺少观察结果，模型无法知道行动是否成功、工具返回了什么，后续 Thought 和 Act 将失去依据，整个循环会陷入盲目状态，最终无法完成复杂任务。

因此，Observe 是 TAO 闭环中不可或缺的一环；少了 Observe，ReAct 就无法实现“感知-决策-执行-反馈”的智能闭环，模型会重新退化为仅凭内部知识作答的“被动应答者”，并可能产生幻觉或错误结论。

## 第 20 题

Q: 「回答正确」和「回答有依据」是一回事吗？RAG 评估里怎么区分它们？

A: 根据参考资料，**“回答正确”和“回答有依据”不是一回事**，RAG 评估体系中通过不同指标来区分它们：

- **“回答正确”** 对应的是 **答案相关性（Answer Relevance）**：衡量生成的答案是否与问题相关且准确。它关注的是模型最终输出本身的质量。

- **“回答有依据”** 对应的是 **上下文召回率（Context Recall）** 和 **上下文精确率（Context Precision）**：
  - **上下文召回率**：检索到的内容是否覆盖了答案所需的所有事实，即“依据是否齐全”。
  - **上下文精确率**：检索到的内容是否真的有助于回答，即“依据是否有效”。

因此，RAG 评估中通过分开衡量“答案相关性”与“上下文召回率/精确率”，来区分“回答正确”和“回答有依据”：前者看答案本身，后者看检索到的资料是否支撑答案。
