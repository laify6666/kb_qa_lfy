# 最全梳理：一文搞懂 RAG 技术的 5 种范式

> 来源：https://cloud.tencent.cn/developer/article/2498870

## 发展历程

自 2021 年 RAG 技术出现之后，RAG 首先被用于 LLMs 的预训练阶段来增强语言模型，随后被用于微调与推理任务中。自 ChatGPT 发布以来，用于推理阶段的 RAG 方法迅速演化出了三种范式：NaiveRAG、AdvancedRAG 与 ModularRAG；2024 年微软开源的 GraphRAG 开启了 RAG 的第四种范式，融合了知识图谱；2024 年下半年 AgenticRAG 出现，是前四种范式的集大成者，且具有自适应性。

## 为什么需要 RAG？

大型语言模型在处理特定领域或知识密集型任务时存在很大局限性，特别是在处理超出其训练数据或需要当前信息的查询时，会产生"幻觉"。为了克服这些挑战，RAG 通过语义相似性计算从外部知识库中检索相关文档块，从而增强 LLM。通过引用外部知识，RAG 可有效减少生成与事实不符内容的问题。

## RAG 的起源

RAG 模型将预先训练的参数记忆（预训练语言模型）和非参数记忆（通过检索机制访问的外部知识库，如维基百科的密集向量索引）结合起来用于语言生成。在知识密集型 NLP 任务上，其性能优于纯参数模型和特定任务的检索提取架构；在语言生成任务中，RAG 模型生成的语言比最先进的纯参数基线模型更具体、更多样、更真实。

## RAG 简单流程与总览

应用于问答的 RAG 过程主要包括 3 个步骤：

1. 索引：文档被分割成块，编码成向量，存储在向量数据库中。
2. 检索：根据语义相似度检索与问题最相关的 Top k 块。
3. 生成：将原始问题和检索到的块一起输入 LLM，生成最终答案。

## 高级 RAG（Advanced RAG）

高级 RAG 引入了具体的改进措施，以克服 Naive RAG 的局限性：

- 为了提高检索质量，采用检索前和检索后策略；
- 为了解决索引问题，通过使用滑动窗口方法、细粒度分割和元数据的整合，改进了索引技术；
- 还采用多种优化方法来简化检索过程。

## 模块化 RAG（Modular RAG）

模块化 RAG 架构超越了前两种范式，具有更强的适应性和多功能性。它将复杂的 RAG 系统分解为独立的模块和专门的运算符，形成一个高度可重新配置的框架。它支持多种 RAG 模式：线性、条件、分支和循环，并引入了路由、调度和融合机制。典型流程阶段包括：索引（Indexing）、预检索（Pre-retrieval，查询扩展、查询转换）、检索（Retrieval）、后检索（Post-retrieval，重排、压缩、选择）、生成（Generation）、协同（Orchestration，路由、调度和融合）。

## GraphRAG

GraphRAG 利用实体间的结构信息，实现更精确、更全面的检索，捕捉关系知识。工作流程包括基于图形的索引（G-Indexing）、图形引导的检索（G-Retrieval）和图形增强的生成（G-Generation）。Graph RAG 通过 LLM 构建图索引：先从文档中提取实体图，再预生成相关实体的摘要；回答问题时，每个摘要生成部分答案，最终汇总为完整回答。它在处理全局性问题（如"数据集的主要主题是什么？"）时，能显著提升答案的全面性和多样性。相关系统还有 LightRAG，将图结构纳入文本索引和检索过程，采用双层检索系统，支持增量更新。

## Agentic RAG

Agentic RAG 将 ReAct 的推理能力与 Agent 的任务执行能力相结合，创建一个动态和自适应的系统。与遵循固定管道的传统 RAG 不同，Agentic RAG 通过使用 ReAct 根据用户查询的上下文动态协调 Agent，引入了灵活性。模型不再仅限于被动响应用户查询；相反，它可以主动规划、执行并调整其方法以独立解决问题，能够处理更复杂的任务，动态适应新挑战。

## 工程实践工具

常用的 RAG 系统构建工具包括 LangChain 和 LlamaIndex（完整框架），以及 FlashRAG（模块化开源工具包，实现了 12 种先进 RAG 方法，提供统一的评估框架和召回率、精确率、F1、BLEU、ROUGE-L 等评估指标）。
